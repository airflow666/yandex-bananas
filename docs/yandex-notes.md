# Требования и лимиты Яндекс Игр — рабочая выжимка

Сверено с живой документацией **29 июля 2026**. Вопреки исходной оценке, доступ к
`yandex.ru/dev/games` из окружения есть, поэтому цифры ниже — не консервативная оценка,
а прямые цитаты. Пометки «не сверено» остались только там, где документация молчит.

## Пункты, по которым пришёл отказ

**1.14** — дословно:

> Нет технических сообщений, ошибок и вылетов, зависаний через некоторое время после
> начала использования или при определенных действиях пользователя.

Пункт перечисляет проверяемые действия: поворот экрана, долгие нажатия по игровому полю,
жесты, свайпы, сворачивание браузера, просмотр рекламы, **навигация по истории браузера**.
Последнее прямо релевантно замечанию модератора про обновление страницы.

**5.1.1.2** — дословно: скриншоты должны показывать настоящий геймплей, занимающий
**не менее 70%** площади изображения; остальное можно отдать под рамки и эффекты.
Соседние подпункты: 5.1.1.1 запрещает чужой геймплей и одинаковые материалы у разных игр,
5.1.1.3 требует ≥70% длительности настоящего геймплея в видео. 5.1.3 требует, чтобы
название игры совпадало во всех материалах черновика для каждого языка.

## Лимиты сохранений (это были главные «на глаз» числа)

| Метод | Размер | Частота |
|---|---|---|
| `setData` / `getData` | 200 КБ на игрока | **100 раз за 5 минут** |
| `setStats` / `incrementStats` / `getStats` | 10 КБ на игрока | **60 раз за 1 минуту** |
| `ysdk.getPlayer()` | — | **20 запросов за 5 минут** |

`setData(data, flush)`: при `flush: false` (по умолчанию) запрос ставится в очередь,
при `flush: true` отправляется немедленно. То есть очередь записи в `core/storage.ts`
частично дублирует то, что SDK уже делает сам — наша очередь нужна ради дебаунса,
объединения изменений и `localStorage`-фолбэка, а не ради обхода лимита.

Лимит `getPlayer` в 20 запросов за 5 минут стоит держать в голове при сценарии
«обновить страницу 5+ раз подряд» из раздела верификации: игрок должен запрашиваться
один раз за загрузку и кэшироваться.

## Реклама — план требует правки

**`onOffline` в SDK v2 нет.** Проверено на двух страницах документации
([/ru/](https://yandex.ru/dev/games/doc/ru/sdk/sdk-adv) и
[/dg/](https://yandex.ru/dev/games/doc/dg/sdk/sdk-adv.html)); verbatim-пример в обеих
содержит ровно три колбэка:

```javascript
ysdk.adv.showFullscreenAdv({
    callbacks: {
        onOpen: () => console.log('Реклама открыта.'),
        onClose: (wasShown) => console.log(wasShown ? 'Показана и закрыта.' : 'Не показана.'),
        onError: (error) => console.log('Ошибка вызова.'),
    }
})
```

Веб-поиск выдавал обратное (колбэк `onOffline` с описанием «при потере сетевого
соединения»), но пересказ поисковика проигрывает двум прямым чтениям страницы с
совпадающим примером — вероятно, это память о SDK v1. Ставить `onOffline` в план не надо;
страховочный таймаут поверх промиса — надо.

Важное уточнение по `onClose`: он вызывается «при закрытии рекламы, **после ошибки**,
а также если реклама не открылась по причине слишком частого вызова». То есть штатно
промис всё же резолвится и в ошибочных ветках — риск вечного зависания рекламы ниже,
чем предполагал план, но не нулевой (колбэк может не прийти, если сам SDK не ответил).

**Частота.** Для rewarded — «не ограничена». Для полноэкранной — «управляется платформой»,
и документация прямо предостерегает от показа по фиксированному расписанию
(пример-антипаттерн — «каждые 3 минуты») и в момент, когда игрок активно взаимодействует
с игрой. Наш кулдаун 60 с и задержка первого показа 90 с этому не противоречат: показ
только между забегами, в естественной паузе, а платформа режет лишнее сама.

## События жизненного цикла — план прав, у нас их нет

```javascript
ysdk.on('game_api_pause', pauseCallback);
ysdk.off('game_api_pause', pauseCallback);
```

- `game_api_pause` — при показе полноэкранной или rewarded рекламы, открытии окна покупки,
  переключении вкладки, сворачивании окна браузера. Игра обязана остановить игровой цикл
  и музыку.
- `game_api_resume` — при закрытии рекламы или окна покупки, возврате фокуса. Возобновить
  цикл и музыку.

Дополнительно существуют: `ysdk.EVENTS.HISTORY_BACK` (только ТВ, кнопка «назад» на пульте),
`ysdk.EVENTS.EXIT` (диспатчим сами после подтверждения выхода),
`ACCOUNT_SELECTION_DIALOG_OPENED` / `ACCOUNT_SELECTION_DIALOG_CLOSED` — на время диалога
выбора прогресса синхронизацию данных надо приостановить, после закрытия — перезапросить
данные игрока. Последняя пара напрямую влияет на `core/storage.ts`.

## Загрузка

`LoadingAPI.ready()` — вызывать, когда игра загрузила ресурсы и готова к взаимодействию.
`GameplayAPI.start()` / `stop()` — старт/возобновление и пауза/завершение геймплея.
Это методы, которые вызываем мы, а не события подписки.

`/sdk.js` подключается относительным путём (абсолютный — только для iframe со своего
домена) и должен быть подключён до `YaGames.init()`; динамическое подключение через
`document.createElement` документация называет равноправным способом.

## Требования к архиву

`index.html` в корне; в именах файлов и папок недопустимы пробелы и кириллица; суммарный
размер распакованных файлов — не более 100 МБ; никаких абсолютных URL на S3 Яндекса и
обращений к внешним доменам.

## Не сверено

- Точные пиксельные размеры промо-материалов (обложки, иконки, скриншотов) — на странице
  требований дана только доля геймплея в кадре; размеры лежат в консоли разработчика.
- Поведение платформы при превышении лимитов частоты `setData` — документация называет
  число, но не описывает, что именно возвращается при превышении.
