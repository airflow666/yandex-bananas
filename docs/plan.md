# План переработки «Банановой башни» — статус

Ведётся с даты полного ребута (переход на vanilla TS + Canvas 2D, коммит `16fec31`).
Отмечено только то, что реально сделано и проверено в этой сессии — остальное осталось
как было сформулировано в исходном плане.

## Арт-дирекция

- [x] Нарисованы 4 концепта на выбор: `concepts/concept-A-jungle.png` (juicy jungle),
  `concept-B-flat.png` (flat minimal), `concept-C-neon.png` (night neon),
  `concept-D-paper.png` (paper cut). Одна и та же композиция (башня, крен, HUD) в
  четырёх стилях — сравнение честное.
- [x] **Прототип A (juicy jungle) взят за базу и переработан.** Претензии к концепту,
  снятые в итерации 3: всё лежало в одной плоскости (нет глубины и кадрирования),
  блок был жёлтым прямоугольником, палитра монохромна, ветер не был виден.
- [x] Палитра, биомы, типографика и метрики в `theme.ts`: 25 цветов вместо 8,
  построены на контрасте температур — джунгли в холодных сине-зелёных, бананы —
  единственное тёплое пятно, поэтому башня читается как фокус без обводок.
  Третичный акцент (коралловые цветы) занимает <2% площади.
- [x] Фон с параллаксом и биомами (`render/background.ts`): пять слоёв с
  коэффициентами 0 / 0.12 / 0.55 / 1 / 1.25 — небо, дальние кроны, гигантские стволы,
  игровой план, передние листья. Воздушная перспектива: дальние слои уводятся в цвет
  дымки биома. Шесть биомов по высоте (подлесок → кроны → над кронами → облака →
  закат → звёзды) с плавным переходом за 8 этажей; каждый — полный пресет освещения,
  а не только цвет фона. Декор: светлячки в подлеске, солнечные лучи, облака, звёзды.
- [x] Блоки переработаны в **ящики с бананами** (`render/tower.ts`, `art/sprites/crate.ts`).
  Голые бананы отвергнуты по ходу работы — стопка бананов не читается как конструкция.
  Ящик собирается 3-slice (торцы фиксированы, доски растягиваются), поэтому угловые
  стойки не искажаются на узких блоках. Идеальная посадка помечена золотой обвязкой,
  а не свечением: свечение копилось на каждом этаже и заливало половину кадра.
  Вариативность бананов — из `hash01` по номеру этажа, не из `Math.random()`.
- [x] Первый проход game feel — партиклы (пыль/листья), тряска камеры, squash-твин
  посадки, вспышка при обрушении. Подробности и границы — Итерация 2 ниже. Пост-FX
  фона (параллакс, декор по биомам) и вариативность самих блоков всё ещё нет.
- [x] Успокоена анимация мелких ярких деталей. Светлячки мигали от 0.35 до 1 на
  2.2 рад/с и рисовались ПОВЕРХ стволов — замер показал, что до 4.6% пикселей ствола
  менялись скачком в каждом кадре, и это читалось как рябь. Теперь их меньше, вдвое
  медленнее, мельче глубина пульсации, и они ушли ЗА стволы (летают в воздухе между
  деревьями, а не сидят на коре). Звёзды успокоены по той же причине. После правки
  тот же замер даёт 0. Методика на будущее: заморозить `s.time` и сравнить кадры —
  если различий нет, отрисовка детерминирована и виновата анимация, а не случайность.

## Итерация 2 — вертикальный срез геймплея

- [x] Маятник на `sin()` вместо линейного хода с отскоком (`game/pendulum.ts`) —
  тайминг читаем, скорость растёт без потолка, но замедляясь.
- [x] Посадка, обрез, идеальное попадание (`game/rules.ts`): допуск в долях ширины,
  а не в пикселях; серия из 4 идеальных подряд **возвращает** ширину блока — раньше
  ширина только сохранялась и отыграться было нельзя.
- [x] Крен башни от центра масс на пружине с затуханием (`game/tower.ts`).
- [x] **Плечо крена ограничено 12 этажами (`LEVER_FLOORS`).** Физически башня
  вращается вокруг фундамента, и на сотом этаже плечо огромно: поворот на 3° уводил
  верхушку на сотни единиц вбок, а фундамент к тому моменту далеко за нижней кромкой
  кадра — глазу не за что зацепиться, и видимый кусок башни ехал вбок целиком,
  выглядя летающим по воздуху. Теперь шарнир на 12 этажей ниже верхушки, то есть
  чуть ниже кадра, и видимая часть честно поворачивается вокруг точки под собой.
  Величина общая для прицеливания (`topOffsetX()`) и отрисовки — разъехаться они
  не могут по построению.
- [x] Отбраковка этажей идёт по реальной высоте кадра, а не по фиксированным
  5 этажам от верхушки: прежний потолок обрезал стопку выше нижней кромки экрана.
- [x] Камера следует за высотой башни (`game/session.ts`).
- [x] Полный цикл меню → игра → результат → сохранение рекорда (`main.ts`).
- [x] **Анимация падения ящика.** Раньше ящик телепортировался на башню, и это
  вводило в заблуждение. Теперь он отцепляется от лианы и летит ~0.26 с с ускорением;
  на время полёта маятник замирает (иначе точка отрыва уехала бы от падающего ящика),
  а новый тап блокируется. Исход считается В МОМЕНТ ТАПА и едет вместе с ящиком:
  тайминг нажатия — единственный навык в игре, и он не должен зависеть от того, что
  успеет измениться за время полёта. Промахнувшийся ящик не останавливается, а
  проваливается мимо башни, кувыркаясь.
- [x] Экран итогов показывается сразу по касанию, без задержки. Пробовал придержать
  его на 0.75 с ради драматургии — читается как зависшая игра; падение мимо всё
  равно видно позади панели.
- [x] Ветер биомов (`game/tower.ts`): ниже 10 этажа безветренно, дальше сила растёт
  по квадрату до потолка `WIND_MAX_ANGLE` (0.11 рад — заметно, но само по себе не рушит
  башню, только усложняет прицеливание) и колеблется двумя наложенными синусами с
  периодами 7.5 и 3.1 с — достаточно медленно, чтобы порыв читался, а не ощущался шумом.
  Подтверждено прогоном симуляции (45–91 идеальных подряд): угол крена растёт от ветра,
  колебания укладываются в ±0.11, обрушения от одного ветра без ошибок игрока не происходит.
- [x] Game feel первый проход (`game/session.ts`, `render/scene.ts`): тряска камеры
  пропорционально грубости посадки (обрезка — по силе толчка, обрушение — на максимум),
  squash-твин верхнего блока при посадке (пивот у нижнего края, спадает без библиотек
  анимации), пылевой всплеск при каждой посадке, ветряные листья, летящие по направлению
  и силе ветра (видно порыв до того, как он качнёт башню), красная вспышка при обрушении.
  Партиклы и твины — часть состояния `Session`, симулируются в `update(dt)`, а не в кадре.
  Пост-FX и декор фона по биомам (второй пункт исходного плана) всё ещё не сделаны —
  см. Итерацию 3.

## Итерация 3 — арт

- [x] Пайплайн спрайтов (`art/svgRaster.ts`): исходник — SVG в бандле, растеризуется
  в offscreen-canvas под ФАКТИЧЕСКИЙ масштаб экрана и пересобирается при его смене
  (поворот, другой монитор, зум). Отсюда «без потери качества на разных устройствах»
  и одновременно требование CLAUDE.md кэшировать графику на старте, а не в кадре.
  Ни одного внешнего запроса: SVG → Blob URL → растр, URL сразу освобождается.
  Отказ растеризации отдельного спрайта не роняет загрузку.
- [x] Спрайты (`art/sprites/`): банан (3 степени спелости), ящик (торец + доски,
  обычный и «идеальный»), обезьяна (4 позы), ствол (тайлится вертикально —
  боковые кромки строго вертикальны, поэтому стык не виден в принципе), перистый
  лист, монстера, бромелия, гибискус, лист лианы, силуэт кроны.
- [x] Обезьяны (`game/monkeys.ts`, `render/tower.ts`): держатся на уровне верхушки,
  ствол за спиной уезжает с параллаксом 0.55 — глаз читает это как подъём. Прыгают
  дугой на каждый новый этаж, ликуют на идеальной посадке, закрывают глаза при
  обрушении. Обратная связь боковым зрением, без текста.
- [x] Лиана вместо троса: кривая по фактическому положению маятника, провисает
  против хода, четыре штриха для цилиндрического объёма, витки и листья по длине.
- [x] Ветер стал видимым: от одного значения `tower.wind` кренятся передние листья,
  дальние кроны, свисающие лианы и обезьяны; плюс индикатор в HUD, показывающий
  силу и направление ДО того, как порыв качнёт башню.
- [x] Адаптивность арта: ширина ствола и размер обезьян выводятся из ширины кадра,
  а не заданы константой. Фиксированные 340 работали на десктопе и разваливались на
  узком телефоне — два ствола оставляли между собой просвет в 45 единиц, поле
  схлопывалось в щель, обезьяны оказывались поверх башни.
- [x] Передний план прибит к рамке и только качается от ветра. Привязка к камере
  была ошибкой: смещение росло вместе с высотой без предела, и к сотому этажу
  листва наползала на игровое поле. У «объектива» параллакса не бывает.
- [ ] Пост-эффекты (bloom на бликах, глубина резкости) — не делались, кадр держится
  на композиции и цвете. Открытый вопрос, нужны ли они вообще.
- [ ] На широком десктопе игровая колонка занимает ~35% ширины кадра. Пустых полей
  больше нет (их заняли стволы и листва), но для промо-скриншотов по п. 5.1.1.2
  этого может не хватить — проверить при подготовке материалов.

## Итерация 4 — звук

- [x] Мастер-шина, компрессор, процедурный реверб (`audio/engine.ts`). Импульсная
  характеристика зала генерируется из шума с экспоненциальным затуханием на старте —
  ни одного аудиофайла в архиве. Каналы IR заполняются независимо, иначе хвост
  схлопывается в моно. AudioContext создаётся ЛЕНИВО, при первом касании: до жеста
  браузер его глушит, и звуки просто пропали бы.
- [x] SFX (`audio/sfx.ts`): отцепление, посадка, идеальная посадка, обрез, обрушение,
  щелчок кнопки, фанфара рекорда. Все ударные звуки — мгновенная атака, различаются
  материалом (полосой фильтра), а не длиной.
- [x] Питч по комбо: серия идеальных попаданий поднимает ноту по мажорной
  пентатонике, и длину серии СЛЫШНО без взгляда на счётчик. Пентатоника выбрана
  потому, что в ней нет полутоновых столкновений — серия из 20 попаданий не
  превращается в какофонию. Громкость слегка падает с ростом серии, иначе высокая
  нота начинает резать слух.
- [x] Адаптивная музыка (`audio/music.ts`): секвенсор с предпросмотром на 150 мс.
  Таймер только ПЛАНИРУЕТ, ноты расставляются по часам аудиоконтекста — ритм не
  плывёт даже при просадке кадров. Пять слоёв (бас, бочка, шейкер, пэд, мелодия)
  вводятся одной величиной «интенсивность», которую задаёт высота башни, поэтому
  переход между биомами плавный сам собой. Гармония — четыре аккорда в эолийском
  ладу, мелодия по минорной пентатонике.
- [x] Звук глохнет при сворачивании вкладки (требование площадки). Проверено
  замером: без фокуса `suspended | gain=0 | music=false`, с фокусом
  `running | gain=1 | music=true`. Все включения и выключения — через рампу, иначе
  щелчок.
- [x] Кнопка отключения звука на всех экранах, кроме модальных. Настройка
  переживает перезагрузку. Этим закрыт пункт чеклиста «есть пауза и отключение звука»
  целиком.
- [x] Симуляция НЕ вызывает звук напрямую: `Session` складывает события в очередь
  (`game/events.ts`), разбирает их `main`. Иначе `update()` перестал бы быть чистой
  функцией времени, и прогонять забег в тесте без звуковой карты стало бы нельзя —
  а именно так мы всё и проверяем.
- [ ] Не сделано: отдельная шина громкости музыки и эффектов в настройках (сейчас
  один общий мьют), приглушение музыки на время рекламы (появится вместе с рекламой
  в итерации 6).

## Итерация 5 — мета

- [x] Биомы по высоте (6 штук) — сделаны в итерации 3, см. `render/background.ts`.
- [x] Мета-модель (`game/progress.ts`) — чистая логика без рендера и платформы,
  прогоняется в тесте целиком. Три горизонта цели РАЗНОЙ длины, и это главное
  решение: задание закрывается за забег-два, достижение за неделю, покупка копится.
  Одного горизонта мало — на любом одном игрок либо не видит прогресса, либо
  упирается в потолок за вечер.
- [x] Задания дня: 3 слота, выводятся из номера суток детерминированно — одинаковы
  весь день, меняются сами в полночь UTC, не требуют ни сервера, ни хранения списка.
  Типы в слотах гарантированно разные (день из трёх «собери бананы» выглядит как
  ошибка генератора). «Этажи за забег» и «серия» считаются РЕКОРДОМ за день, а не
  суммой — иначе «построй 30 этажей» выполнялось бы само собой.
- [x] Достижения: 10 штук с растущим шагом. Первые два-три закрываются в первые же
  забеги намеренно — пустой список наград хуже всего показывать новому игроку.
- [x] Магазин: 6 скинов ящика, 150–1200 бананов. Технически скин не набор спрайтов,
  а тонировка умножением поверх отрисованного ящика: светотень и текстура досок
  сохраняются, растровый кэш не растёт впятеро. Трата ЧИСТО косметическая — иначе
  игра превращается в «накопи и выиграй», а рекорд перестаёт сравнивать умение.
- [x] Второй режим «Шторм» (`game/modes.ts`): не копия кода, а набор коэффициентов
  к той же симуляции — любая правка баланса действует в обоих режимах. Ветер уже
  разогнан на старте (через отрицательный `windFrom`), маятник +25%, награда ×1.5,
  рекорд отдельный. Открывается за 20 этажей в классике.
- [x] Ежедневный бонус 40–120 бананов, растёт с числом забегов до потолка. Даётся
  при заходе, а не по кнопке.
- [x] Проверено прогоном: рекорды режимов раздельные, задания копятся правильно
  (максимум против суммы), достижения выдаются по факту, награда забирается один раз,

## Проверка на соответствие требованиям (перед сдачей)

Прогон по действующей документации, а не по памяти. Найдено и исправлено
пять реальных нарушений — все были не замечены прошлыми прогонами:

- [x] **Реклама всплывала поверх геймплея.** `void maybeInterstitial()` не
  ожидался, забег стартовал в ту же миллисекунду. Прямое нарушение п. 4.4.
  Теперь ролик ожидается, забег начинается после его закрытия.
- [x] **GameplayAPI не возобновлялся.** `onPause` звал `gameplayStop()`, а
  `onResume` `gameplayStart()` не звал — после сворачивания вкладки посреди
  забега площадка до самого конца считала бы, что геймплея нет (п. 1.19).
- [x] **Упоминание площадки в интерфейсе игры.** Строка «Таблица доступна на
  Яндекс Играх» показывалась игроку. В архиве теперь 0 упоминаний — проверено
  поиском по `dist/`.
- [x] **`overscroll-behavior: none` отсутствовал**, хотя чеклист прошлой
  сессии утверждал обратное. Один `touch-action` swipe-to-refresh не гасит.
- [x] **Двуязычная надпись «Загрузка… / Loading…»** на старте заменена на
  языконезависимую CSS-анимацию из трёх ящиков, собирающихся в башню: до

- [x] Кнопка входа убрана по решению заказчика — игра целиком гостевая.
- [x] Отсутствие внешних запросов подтверждено ЗАМЕРОМ сетевой панели, а не
